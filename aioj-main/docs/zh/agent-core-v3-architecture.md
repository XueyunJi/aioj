# Agent Core V3 架构

[English](../en/agent-core-v3-architecture.md)

## 设计目标

Agent Core V3 为学生 AI 助教提供可审计、可约束、可恢复的运行架构。模型负责语言理解与受限规划，服务器负责身份、授权、数据范围、工具执行、比赛策略、预算与最终输出检查。

核心假设是：**模型是不可信规划器，服务器是可信控制面**。模型输出不能直接改变权限、读取任意数据、执行任意工具或写入长期记忆。

## 在线 Turn

```text
用户请求
  -> 服务端建立 Turn 与身份/策略快照
  -> 构建最小 Bootstrap Context
  -> 模型提出回答或工具请求
  -> 服务端逐次授权并执行工具
  -> 汇总受信数据与模型输出
  -> 输出安全检查
  -> 持久化回答、用量、工具与审计证据
  -> 异步生成可检索摘要
```

每个 Turn 有稳定 ID 和终态。重试按 Turn 幂等，避免重复计费、重复审计或重复记忆候选。Provider 失败、工具失败或摘要延迟不会绕过服务端策略。

## 上下文分层

原始会话与业务数据始终是权威源；摘要、索引、向量和记忆都是派生数据。

1. **Bootstrap Context**：当前用户、会话、题目、比赛和能力边界的最小可信摘要。
2. **Turn 摘要**：每轮结构化记录主题、实体引用、决定与未解决问题。
3. **Episode 摘要**：跨多轮的阶段性上下文。
4. **原始证据回取**：回答关键事实前回取受权原文或业务记录。
5. **精确检索兜底**：摘要召回不足时使用受限关键字或实体检索。

检索结果携带来源、范围和可信等级。未经验证的模型陈述不能被提升为用户事实。

## 工具控制面

模型只看到当前场景允许的工具描述。每次调用都由服务器重新检查：

- 当前用户与角色；
- 当前会话、题目、比赛运行和时间窗口；
- 工具参数 Schema；
- 数据可见性与最小返回字段；
- 调用预算、超时和循环上限；
- 审计与隐私要求。

工具结果使用结构化数据并标注可信来源。网页、题面、用户内容和模型文本都不能作为系统指令改变工具权限。

## 记忆与学习画像

长期记忆保存稳定、可复用且有证据的用户偏好或事实；学习画像保存从提交、复盘和行为信号推导的能力状态。两者分离，避免把一次题目知识点或 AI 建议误当作长期偏好。

```text
证据 -> 候选 -> 质量/冲突检查 -> 用户确认 -> 生效 Claim
```

模型只能提出候选。服务端保存证据、来源和状态；用户可以接受、拒绝或撤销。冲突 Claim 不静默覆盖，画像信号保留时间与来源。

## 比赛安全

比赛防护使用四层服务端边界：

1. **参赛判定**：服务器根据当前运行、参与者和时间窗口判断约束范围。
2. **策略快照**：将运行发布时固化的 AI 策略注入当前 Turn。
3. **问题匹配**：使用运行题目快照与受限指纹判断用户是否在询问比赛题。
4. **输出检查**：返回前检查完整代码、私有题信息与其他受限内容。

客户端传入的 `problemId` 或比赛上下文只用于体验和统计，不能作为可信授权依据。私有题面、隐藏测试和其他参与者源码不会发送给模型用于判断。

## Prompt Injection 防护

- 指令权只来自可信服务器配置和受控策略。
- 用户文本、历史消息、题面、工具结果和检索内容都标记为数据，不可修改系统权限。
- 工具返回结构化字段，不拼接成可执行系统指令。
- 记忆写入经过独立候选与确认流程。
- 最终回答在返回前执行内容与策略检查。

## 审计与用量

每轮保存必要的模型调用、Token 用量、工具调用、策略决策、降级状态和追踪关联。审计只保留安全摘要，不记录密钥、隐藏测试、完整内部错误或无关个人数据。

比赛 AI 用量按服务端可信运行归属统计对话轮次、输入/输出 Token、会话数和拦截数；统计观察不改变回答、配额或 Agent 规划。

## 失败与降级

- Provider 不可用：返回安全、可追踪的降级错误，不伪造 Token 或事实。
- 工具超时：停止该调用并保留审计，不能绕过权限改用数据库直读。
- 摘要或索引延迟：回退到授权的近期上下文或精确检索。
- 比赛策略依赖异常：遵循安全默认并记录降级证据。
- 输出检查失败：拒绝或收敛输出，而不是返回未检查内容。
