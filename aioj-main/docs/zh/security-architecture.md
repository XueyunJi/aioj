# 安全架构

[English](../en/security-architecture.md)

## 目标

AIOJ 同时处理不可信用户代码、身份凭据、隐藏测试、比赛题目、参与者源码和 AI Provider 数据。安全架构采用最小权限、服务端授权、数据最小化、异步隔离、可审计性和纵深防御。

## 数据分类

| 数据 | 保护要求 |
| --- | --- |
| 密钥、令牌、数据库凭据 | 仅服务器秘密存储，禁止进入 Git、镜像层、日志与客户端 |
| 隐藏测试与测试包 | 文件/卷存储，按题目与判题任务授权，禁止公开下载 |
| 参与者源码 | 学生本人可见；教师访问使用受审计 API；查重导出默认不含完整源码 |
| 私有比赛题面 | 仅符合运行参与者与时间策略的请求可见 |
| AI 对话、记忆和画像 | 最小收集、按用户授权、可追踪来源，候选需用户确认 |
| 评测输出 | 客户端只接收产品所需摘要，内部完整输出受限且有边界 |

## 身份与授权

网关是浏览器入口，但最终业务授权由目标服务执行。JWT、角色和资源归属共同决定权限；内部服务令牌不能替代用户级资源检查。前端隐藏按钮不是安全控制。

## 判题隔离

problem-service 只发布任务，judge-worker 只编排并调用 Sandbox。Sandbox 不能访问 Docker socket、host network、业务目录、数据库、JWT、AI 或部署秘密；测试包只读，临时工作区独立，CPU、内存、PID、时间、输出和日志有界。

### 特权 Sandbox 风险

当前 go-judge 集成使用 `privileged` 容器。正常代码受命名空间、cgroup 与执行限制约束，但成功利用 Sandbox、Docker、容器运行时或 Linux 内核漏洞仍可能：

- 获得宿主机 root 等价控制；
- 读取或篡改数据库、用户数据、密钥和令牌；
- 修改评测结果、镜像、容器或内部流量；
- 访问 MySQL、Redis、RabbitMQ 与业务服务；
- 耗尽 CPU、内存、进程、磁盘或网络；
- 建立宿主机级持久化。

单节点部署扩大了该风险的影响范围和单点故障范围。内部网络、只读挂载、资源限制和秘密隔离是必要补偿控制，但不能让单节点与独立判题节点达到等价安全。

## AI 安全

- 模型和模型输出不可信，授权和工具执行在服务端。
- 私有题面、隐藏测试和无关个人数据不发送给 Provider。
- Prompt、工具结果和召回内容区分指令与数据来源。
- AI 查重与复盘是建议性证据，不能自动形成纪律处分或最终成绩。
- 记忆写入需要候选、证据、冲突检查和用户确认。

## 秘密与交付

GitHub 只保存发布所需的受限部署身份与固定主机密钥材料；应用与 GHCR 读取凭据留在服务器 root-only 配置。生产使用不可变镜像 digest，不使用 `latest`，服务器不保存 Git 工作树。

## 恢复边界

生产备份只来源于生产服务器，并同时保护数据库、消息状态、测试包和必要产物。镜像回滚使用当前数据卷；成功执行的 Flyway 不自动回滚。恢复或清理是独立授权操作，不能由应用发布顺带执行。

## 责任披露

安全问题应通过维护者已验证的私密渠道报告。不得在公开 Issue 中发布凭据、个人数据、隐藏测试、私有源码、基础设施细节或可直接利用的攻击步骤。
