# 比赛与用户组架构

[English](../en/contest-and-user-group-architecture.md)

## 组织模型

用户组是唯一维护的教学组织模型，用于成员管理、比赛运行报名资格、参与者导入以及教师/管理员权限检查。已移除的学习小组和旧训练报告模型不属于当前产品架构。

## 蓝图与运行

`contest` 是可复用蓝图，保存标题、说明、赛制、计分规则和题目编排。

`contest_run` 是一次具体开放，保存开始、结束与封榜时间，报名策略、允许用户组、参与者、提交、排行榜、审计、公告、澄清、查重和复盘。所有运行级操作必须携带明确 `runId`，默认不能跨运行聚合。

```text
contest blueprint
      |
      +-- contest_run A -> snapshots -> participants -> submissions -> reports
      |
      `-- contest_run B -> snapshots -> participants -> submissions -> reports
```

## 生命周期

草稿运行可以配置但不对学生开放。发布时固化规则、题目与可见性快照。非草稿运行根据服务器时间派生已排期、进行中或已结束状态；超过结束时间但尚未归档的运行只允许归档相关治理操作。归档与软删除优先于时间派生状态。

## 快照

- 参与者加入或获批时保存必要身份快照。
- 运行发布时保存题面、可见性、规则与 AI 策略快照。
- 历史排行榜、提交和报告使用运行快照，不能受后续题目或用户资料修改影响。

## 报名与邀请

公开报名根据时间窗口、审核要求、人数与用户组资格决定是否加入。私有邀请可以在草稿期保存，但只有运行发布后才对学生可见并发送通知。接受邀请与打开运行使用相同的服务端可访问条件，避免“已接受但无法进入”。

## 计分

### ACM

按解题数降序、罚时升序、最后通过时间和稳定显示顺序排序。封榜后提交显示为 pending，解封或 resolver 过程再逐步公开。

### IOI/OI

按总分降序和最后改进时间排序。子任务与测试点结果可以作为分数证据，但隐藏测试内容始终不可见。

## 公告与澄清

公告和澄清均属于一个具体运行。公告可以置顶和归档；澄清由一个问题和一个正式回复组成。公开回复对有资格的学生可见但隐藏提问者身份，私有回复只对工作人员和提问学生可见。

## AI、查重与复盘

- 比赛期间 AI 策略由运行快照和服务端参赛状态决定。
- AI 查重输出相似度证据与风险信号，不做纪律处分决定。
- 个人与教师复盘只使用授权的运行、提交和评测摘要，不包含隐藏测试或其他参与者隐私。
- 学生薄弱点候选必须经学生接受后才写入长期记忆。

## 审计与隐私

教师查看比赛源码、导出证据、执行查重、生成复盘和治理运行状态都需要审计。导出与 UI 默认提供最小必要证据，不能暴露完整他人源码、密钥或完整评测输出。
